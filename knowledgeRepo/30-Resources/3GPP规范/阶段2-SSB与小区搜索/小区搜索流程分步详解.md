# 细节：小区搜索流程分步详解

## 一句话

小区搜索 = UE 从“完全不知道时间和频率”到“能读 SIB1、知道怎么接入”的过程。每一步都在减少不确定性：PSS 给出粗同步和 N_ID^(2)，SSS 补上 N_ID^(1) 得 PCI，PBCH DM-RS 给出 SSB index 低位并帮助解 PBCH，MIB 给出 SFN 与 CORESET#0，最后通过 Type0-PDCCH 的 DCI 1_0 拿到 SIB1。

## 全景：不确定性是怎么一步步消除的

| 步骤 | UE 此时知道什么 | 还不知道什么 |
| --- | --- | --- |
| 频点扫描（实现相关） | 在哪个候选频点上有能量 | 时间、PCI、帧号 |
| PSS 检测 | 符号定时、频偏粗估计、N_ID^(2) | N_ID^(1)、SSB index、SFN |
| SSS 检测 | N_ID^(1)，进而得 PCI = 3·N_ID^(1)+N_ID^(2) | SSB index、SFN、网格参数 |
| PBCH DM-RS | SSB index 低位（2/3 bit）+ PBCH 信道估计 | MIB 内容、SIB1 在哪 |
| PBCH/MIB 解码 | SFN、k_SSB、SIB1 的 SCS 与 CORESET#0/SS0 | Point A、SIB1 具体内容 |
| Type0-PDCCH（DCI 1_0 / SI-RNTI） | SIB1 的 PDSCH 调度信息 | SIB1 内容 |
| PDSCH/SIB1 解码 | Point A、载波/BWP、PLMN、接入参数 | ——（可进入小区选择/接入） |

## Step 1：PSS——粗同步 + N_ID^(2)

- 规范：38.211 §7.4.2.2（序列生成）、§7.4.3.1（映射）。
- PSS 是 127 长的 m 序列，映射在 SSB 第 0 个符号的中间 127 个子载波（k=56..182），BPSK 式 ±1 符号。
- 只有 **3 个候选序列**，对应 N_ID^(2) ∈ {0,1,2}。UE 在接收信号里做相关，找出：
  1. 最强相关峰 → N_ID^(2)；
  2. 峰的位置 → OFDM 符号起点（粗定时）；
  3. 峰与预期频偏的关系 → 载波频偏（CFO）估计（小数倍频偏为主）。
- 输出：符号级定时、频偏粗估计、N_ID^(2)。此时还不知道帧/子帧边界。

## Step 2：SSS——N_ID^(1)，合成 PCI

- 规范：38.211 §7.4.2.3。
- SSS 也是 127 长序列，由两个 m 序列做逐点乘积得到，位于 SSB 第 2 个符号中间 127 个子载波，与 PSS 相隔固定 2 个符号。
- 336 个候选对应 N_ID^(1) ∈ {0,…,335}；SSS 的两个循环移位 m0/m1 按 N_ID^(1) 与 N_ID^(2) 联合设计（m0 = 15·⌊N_ID^(1)/112⌋ + 5·N_ID^(2)，m1 = N_ID^(1) mod 112）。
- 知道 N_ID^(2) 后做 336 路相关，得 N_ID^(1)，于是：
  PCI = 3·N_ID^(1) + N_ID^(2)，共 1008 个。
- PSS 与 SSS 的固定相对位置也帮忙把定时从“符号级”推进到“SSB 内符号位置级”，但仍不知道在帧/半帧的哪里。

## Step 3：PBCH DM-RS——SSB index 低位 + 信道估计

- 规范：38.211 §7.4.1.4（PBCH DM-RS 序列/映射）、§7.4.3.1。
- PBCH DM-RS 共 144 个 RE：第 1、3 符号每个 60 个，第 2 符号两侧 24 个；梳齿间隔 4，起始位置 v = PCI mod 4。
- 两个作用：
  1. **解调参考**：估计信道，用于 PBCH 的 QPSK 解调；
  2. **携带 SSB index 低位**：DM-RS 序列 index 与 SSB index 映射——L_max=4 时给 2 个 LSB，L_max>4 时给 3 个 LSB。
- SSB index 高位不在 DM-RS 里，而在 PBCH 载荷的 ā̄ 位（见 Step 4），所以“先解 DM-RS 拿低位 → 解 PBCH 拿高位”是一条链。

## Step 4：PBCH / MIB——SFN、k_SSB、CORESET#0

- 规范：38.212 §7.1（编码链）、38.331（MIB）、38.211 §7.4.3.1（映射）。
- PBCH 数据 432 个 RE、QPSK → 864 bit；编码链：32 bit 载荷 → 加扰 → 24 bit CRC → Polar → 速率匹配 864。
- 32 bit 载荷里：
  - MIB 字段（38.331，23 bit）：SFN 6 MSB、subCarrierSpacingCommon、ssb-SubcarrierOffset（k_SSB 低 4 位）、dmrs-TypeA-Position、pdcch-ConfigSIB1（8 bit）、cellBarred、intraFreqReselection、spare；
  - 物理层附加 8 bit：SFN 4 LSB、半帧指示位 HRF、3 个 ā̄ 位（作用随 L_max 变化：k_SSB 最高位 / SSB index 高位 / Type0-PDCCH 相关指示）。
- 解码后 UE 知道：
  - **完整 SFN**（MIB 6 MSB + 附加 4 LSB，10 位）；
  - SSB 相对 RB 网格的子载波偏移 k_SSB（还缺 Point A，因为 offsetToPointA 在 SIB1）；
  - SIB1/Msg2/4 用的 SCS（subCarrierSpacingCommon）；
  - CORESET#0 与 SearchSpace#0 的索引（pdcch-ConfigSIB1 = 4+4 bit，查 38.213 §13 的表）。
- PBCH 有 80 ms TTI 概念：同一 BCH 传输块在 80 ms 内重复，UE 需要盲检/软合并来确定 80 ms 边界（细节与 Polar 一起学，阶段 4）。

## Step 5：Type0-PDCCH CSS——用 DCI 1_0 找 SIB1

- 规范：38.213 §13（Type0-PDCCH CSS）、§10 相关（监测）、38.212 §7.3（DCI 1_0）。
- MIB 里 pdcch-ConfigSIB1 的 4 bit controlResourceSetZero + 4 bit searchSpaceZero，查表得到：
  - CORESET#0：时频大小（RB 数、符号数）与相对 SSB 的频域偏移；
  - SearchSpace#0：监测时机（哪些帧/时隙/符号）。
- UE 在这些时机监听 PDCCH，盲检 **DCI 1_0（fallback 格式），CRC 用 SI-RNTI 加扰**（SI-RNTI = 0xFFFF）。
- DCI 1_0 里带着 SIB1 的 PDSCH 调度：时频资源分配、MCS/TBS、DM-RS 等。
- SIB1 默认以 160 ms 为周期调度，一个周期内可重复发送；具体监测位置与 SSB index、searchSpaceZero 表相关（进入阶段 3 后精读）。

## Step 6：PDSCH / SIB1——补全网格，可以接入

- 规范：38.331（SIB1 / ServingCellConfigCommonSIB）、38.214（PDSCH 接收，阶段 5）。
- SIB1 在初始 DL BWP 里用普通 PDSCH 收；里面包含：
  - **offsetToPointA、SCS-SpecificCarrierList**（frequencyInfoDL）→ 至此 UE 才算出 Point A 与完整 CRB 网格；
  - initial DL/UL BWP（locationAndBandwidth、subcarrierSpacing）；
  - TDD 配置（tdd-UL-DL-ConfigurationCommon）、PRACH 配置等接入参数；
  - cellSelectionInfo、PLMN（经上层）等。
- 拿到 SIB1 后，UE 才算“站在能接入的门前”；之后做小区选择/驻留，进入随机接入（阶段 7 相关内容）。

## 时序小抄（先记这几个数）

- SSB：4 个符号 × 20 RB；一个突发（burst）里最多 L_max 个候选 SSB，只在半帧（5 ms）内出现。
- 初始小区选择：含 SSB 的半帧默认每 2 帧（20 ms）一次；接入后可配更短周期。
- PBCH/BCH TTI：80 ms（8 帧），涉及软合并与 SFN 边界判断。
- SIB1：默认 160 ms 周期调度；靠 Type0-PDCCH 的 DCI 1_0（SI-RNTI）定位。
- PCI：1008 个 = 3（PSS）× 336（SSS）。

## 易错点

- PSS 只给 N_ID^(2)（3 选 1），SSS 才给 N_ID^(1)（336 选 1）；相关次数差了两个数量级，实现上先 PSS 后 SSS 就是为了少算。
- SSB index 低位在 DM-RS 序列里，高位在 PBCH 载荷里；两者缺一不可。
- SFN 共 10 位：6 位 MSB 在 MIB，4 位 LSB 在 PBCH 附加位（不在 MIB 编码内）。
- k_SSB 只是“SSB 相对网格的子载波偏移”，Point A 要等 SIB1 的 offsetToPointA 才完整；别把 k_SSB 当成绝对频点。
- CORESET#0/SearchSpace#0 是 Type0-PDCCH CSS 的默认配置来源，但只覆盖“找 SIB1/系统信息”这一阶段；RRC 配置后的 PDCCH 用别的 CSS/USS（阶段 3）。

## FAQ：PSS/SSS 的“127 与候选数量”

**问：127 长的序列是不是也只有三种？**

不是。“长度 127”和“候选数量”是两回事：

- PSS：长度 127，确实只有 **3 种**——同一条 m 序列的 3 个循环移位（移位量 43·N_ID^(2)，N_ID^(2)=0/1/2），所以 PSS 相关只要做 3 路。
- SSS：长度也是 127，但不是 3 种。它由两条 m 序列 x0/x1 分别做循环移位 m0/m1 后相乘得到：m1 = N_ID^(1) mod 112（112 种），m0 = 15·⌊N_ID^(1)/112⌋ + 5·N_ID^(2)（9 种组合）。合计 112×9 = 1008 个可能序列，正好覆盖 1008 个 PCI。
  - 若先已知 N_ID^(2)（PSS 已解出），则只需在 **336 个** N_ID^(1) 候选中相关——这就是笔记里写“SSS 336 选 1”的语境。

**问：N_ID / 序列携带什么信息？是固定的吗？**

- PSS/SSS 序列本身只携带 PCI：PSS 给 N_ID^(2)，SSS 给 N_ID^(1)，合起来 N_ID^cell = 3·N_ID^(1)+N_ID^(2)。PCI 只是一个 0–1007 的“身份号”，本身不携带频段、运营商或任何配置。注意：除了“序列编码的信息”，检测过程还顺带拿到符号定时、频偏粗估计等同步量——那些是相关峰检测的副产品，不是序列里编码的比特。
- 但 PCI 一旦确定，就固定了一批“种子”：PBCH 加扰、PBCH DM-RS（v = PCI mod 4）、其他参考信号/跳频的 c_init 等都由它推导，所以 UE 拿到 PCI 后才能继续解 PBCH 及后续信道。
- 对一个小区而言 PCI 是固定的（由运营商做 PCI 规划，相邻小区要错开）；规范里序列定义也是固定的，同一 PCI 在任何帧、任何 SSB 里都用同一条 PSS/SSS——它不像 SFN 那样逐帧变化。

**问：都是 127 长，为什么 N_ID^(1)（336）比 N_ID^(2)（3）多这么多？**

数量不是被“127”限制的，而是设计上把“先导序列”保持极小候选数、把“信息容量”放在第二阶段：

- PSS 是 UE 在完全不知道定时/频偏时第一个要检测的信号，通常要对很多时间位置做相关。让它只有 3 个候选（同一 m 序列的 3 个循环移位，移位 0/43/86，间隔约 1/3 长度），是为了：相关次数少、抗频偏/定时误差的歧义小、检测最稳。若把更多 ID 塞进 PSS，需要更多移位，移位间隔变小，频率偏移时容易认错。
- SSS 在 PSS 之后检测：此时符号定时、N_ID^(2) 已知，只需在固定对齐位置做 336 路相关，计算量可接受。它用两条 m 序列相乘、各自循环移位来扩容：m1 有 112 种（密），m0 只有 9 种且取值很稀疏（0/5/10/…/40），兼顾“候选多”和“移位彼此可分”。
- 历史延续：LTE 就是 3（PSS）× 168（SSS）= 504 个 PCI；NR 把 SSS 侧扩到 336，变成 3 × 336 = 1008，几乎把翻倍都放在 SSS 上，PSS 的“3”原样保留。

**问：锁定后，下一个 10 ms 帧里符号/SSB 内部位置还保持吗？**

分两层看：

- **符号边界**：保持。gNB 的下行帧结构按 10 ms 严格周期重复（一帧正好 1 966 080 × T_c），PSS/SSS 在 SSB 内的相对位置（PSS=符号 0、SSS=符号 2）是规范固定的。UE 首次锁定后靠跟踪环持续校正本地时钟漂移，符号相位参考可以一直沿用；移动/多普勒场景只是需要继续跟踪，不是每帧重新随机。
- **SSB 出现的时机**：不保证每个 10 ms 都有。SSB 只出现在“含 SSB 的半帧”里，且初始小区选择默认这种半帧每 2 帧（20 ms）出现一次，接入后可配 5/10/20/40/80/160 ms。所以准确说法是：“下一个含 SSB 的半帧里，候选位置和 Case 图案与这次相同”，而不是“下一帧同一位置一定还有 SSB”。

另外注意：符号相位锁定 ≠ 知道帧号。具体是第几帧、第几个半帧、哪个候选 SSB，仍要等 PBCH 的 SFN/HRF 和 DM-RS 里的 SSB index 低位。

**问：SSB 在不同 band 里出现在帧中的位置是固定的吗？**

分两层说，结论是“候选格栅固定，实际出现不固定”：

- **候选位置（candidate positions）固定**：未配 `ssbSubcarrierSpacing` 时，频段决定 SSB 的 Case（38.101-1 Table 5.4.3.3-1，如 n1 是 Case A、n78 是 Case C），Case 决定“半帧内候选 SSB 的首符号位置”（38.213 §4.1，符号 0 = 半帧第 1 个时隙的第 1 个符号）。FR1 常用：
  - Case A（15 kHz）：`{2,8} + 14n`；≤3 GHz 时 n=0,1（L_max=4），FR1 >3 GHz 时 n=0..3（L_max=8）；
  - Case B（30 kHz）：`{4,8,16,20} + 28n`；≤3 GHz 时 n=0，>3 GHz 时 n=0,1；
  - Case C（30 kHz）：`{2,8} + 14n`；配对频谱 ≤3 GHz 时 n=0,1，>3 GHz 时 n=0..3（非配对频谱以 1.88 GHz 为分界）。
  FR2 的 Case D（120 kHz）/Case E（240 kHz）同理，只是 SCS 与 n 集合不同；>52.6 GHz 还有 Case F/G。
- **实际发送不固定**：候选只是“最多 L_max 个可放的位置”。网络可以只发其中一部分（`ssb-PositionsInBurst` 位图），含 SSB 的半帧周期可配 5/10/20/40/80/160 ms；初始小区选择时 UE 才默认“含 SSB 的半帧每 2 帧（20 ms）出现一次”（38.213 §4.1）。所以不能说“每个帧的固定位置一定有个 SSB”。

**问：做完 PSS+SSS 只知道 PCI、不知道 frame/subframe 位置，对吗？**

对，准确说法是：PSS+SSS 把时间定位推进到“**符号级/SSB 内部**”，但到不了“**帧内哪个候选、哪个半帧、哪一帧**”：

- 能得到：N_ID^(2)（PSS）与 N_ID^(1)（SSS）→ PCI；相关峰位置给出 PSS 符号 0 的本地时刻；PSS 与 SSS 相隔固定 2 个符号，所以 SSB 内部符号位置也定了。
- 得不到：所有候选 SSB 的 PSS/SSS 序列完全一样（只依赖 N_ID^(2)/PCI，与 i_SSB、半帧号、SFN 无关），所以即使知道 Case，也只知道“这个 PSS 可能是 `{2,8}+14n` 等若干候选之一”，不知道：
  1. 它是半帧内第几个候选 SSB（i_SSB）——低位来自 PBCH DM-RS 序列号（L_max=4 给 2 bit，L_max=8/64 给 3 bit；L_max=64 的高 3 bit 在 PBCH 载荷）；
  2. 它在第 1 还是第 2 个半帧（PBCH 附加位里的半帧指示）；
  3. 它在第几帧（SFN：4 LSB 在 PBCH 附加位，6 MSB 在 MIB）。
- 时间层级小结：**PSS/SSS → 符号；DM-RS → 半帧内候选 index；PBCH/MIB → 半帧号 + 帧号（SFN）**。这也是为什么 OAI 的 `nr_search_ssb_common` 一路做到 `nr_pbch_detection`（Polar 解出 PBCH）才把 `cell_detected` 置真。

**问：Case A 下 PSS/SSS 能不能确定是符号 2 还是 8？n 是 PBCH 给的吗？**

先纠正一个写法：Case A 的候选是 `{2, 8} + 14n`（一个 slot 14 个符号，所以步进是 **14**，不是 12）。

- PSS/SSS 只能告诉你“这里有一个 SSB、它的符号 0 在这个位置”，但所有候选的 PSS/SSS 都一样，所以**分不清是符号 2 还是 8，也算不出 n**。说得再细一点：把 slot 边界放在“SSB 起点往前 2 个符号”或“往前 8 个符号”都自洽，二者只差 6 个符号，存在相位歧义；n（半帧内第几个 slot）更是完全没信息。
- 真正给位置的是 **PBCH DM-RS 的序列号 → i_SSB**（38.213 §4.1：L_max=4 给 2 LSB，L_max=8/64 给 3 LSB），再由 i_SSB 反查候选位置表：
  - Case A、L_max=4（≤3 GHz）：i_SSB=0..3 按时间升序对应 `{2,8}+14n` 的 n=0,1 → 即 符号2/符号8（n=0）、符号16/符号22（n=1）；
  - Case A、L_max=8（FR1 >3 GHz）：i_SSB=0..7 对应 n=0..3 的符号 2/8，共 8 个。
  - 换算关系（Case A）：`n = ⌊i_SSB / 2⌋`，符号组 = 2 还是 8 由 `i_SSB mod 2` 决定。
- 所以严格说不是“PBCH 数据载荷给 n”，而是“**DM-RS 序列号给 i_SSB，n 由 i_SSB 推导**”；PBCH 载荷负责的是半帧号、SFN 4 LSB，以及 L_max=64 时 i_SSB 的高 3 位。
- 为什么没有 n 也能继续解 PBCH：SSS/PBCH/DM-RS 都在同一个 4 符号块里，相对位置固定，UE 拿到 PSS 定时后直接按“块起点 + 0/1/2/3 符号”做 FFT 和解调即可，不需要先知道 n；OAI 的 `nr_pbch_detection` 就是在这一步对“候选 index × 半帧”做 DM-RS 相关 + Polar 解码确认。
