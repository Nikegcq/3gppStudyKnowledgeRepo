# 概念：嵌入式总线对比（CAN / CAN FD / RS485 / SPI / I2C）

## 一句话总结

这五个"总线"根本不在一个层面上：**RS485 只是物理层**，**CAN/CAN FD 是带仲裁与错误管理的完整链路层**，**SPI/I2C 是板内短距的芯片间总线**。选型先看四件事：距离、节点数/拓扑、实时性与可靠性要求、需不需要多主。

> 电气、成帧、时序层面的机制拆解见 [[概念-嵌入式总线-原理详解]]。

## 1 总览对比

| 维度 | CAN 2.0 | CAN FD | RS-485 | SPI | I2C |
| --- | --- | --- | --- | --- | --- |
| 协议层次 | PHY + MAC/LLC | PHY + MAC/LLC | **仅 PHY** | PHY + 简单链路（无标准） | PHY + 简单链路 |
| 线数 | 2（差分） | 2（差分） | 2（半双工）/ 4（全双工） | 4（SCLK/MOSI/MISO/CS） | 2（SDA/SCL） |
| 拓扑 | 总线型多主 | 总线型多主 | 总线型多点到多点 | 一主多从（点对点片选） | 总线型多主多从 |
| 双工 | 半双工 | 半双工 | 半双工 / 全双工 | **全双工** | 半双工 |
| 典型速率 | ≤1 Mbit/s | 仲裁段 ≤1 Mbit/s，数据段 2–5 Mbit/s（非 ISO 可更高） | 100 kbit/s～10 Mbit/s | 10–100 MHz+ | 100 k/400 k/1 M/3.4 M/5 M |
| 典型距离 | 40 m@1M，1000 m@50k | 与 CAN 类似，但高速段更短 | **1200 m@≤100k** | 板内（<1 m） | 板内（<1 m） |
| 寻址 | 11/29-bit 报文 ID | 同 CAN | 无（靠上层协议） | 片选 CS | 7/10-bit 地址 |
| 仲裁 | **非破坏性逐位仲裁** | 同 CAN | 无 | 无 | 多主仲裁（线与） |
| 错误检测 | CRC15 + ACK + 错误帧 + 错误计数 | CRC17/21 + 更强机制 | 无（靠上层） | 无 | ACK/NACK（弱） |
| 最大载荷 | 8 B | **64 B** | 不限（字节流） | 不限（字节流） | 不限（字节流） |
| 典型场景 | 车载、工控、电机 | 车载新平台、需要大数据量 | Modbus、Profibus、DMX | Flash、ADC/DAC、RF 芯片 | EEPROM、PMIC、传感器、时钟芯片 |

## 2 CAN 2.0

### 2.1 电气与拓扑

- 差分对 **CAN_H / CAN_L**，显性位（dominant，逻辑 0）与隐性位（recessive，逻辑 1）
- 显性覆盖隐性（线与）→ 这是**非破坏性仲裁**的物理基础
- **总线两端各 120 Ω 端接**（中间节点不接），必须走直线拓扑，分支（stub）尽量短
- 高速 CAN（ISO 11898-2）常用收发器：TJA1050、MCP2551、ISO1042（隔离）

### 2.2 帧结构（数据帧）

| 字段 | 说明 |
| --- | --- |
| SOF | 1 位显性，帧起始 |
| 仲裁段 | 11 位标准 ID（2.0A）或 29 位扩展 ID（2.0B），含 RTR |
| 控制段 | IDE、r0、DLC（0–8 字节） |
| 数据段 | 0–8 字节 |
| CRC | CRC-15 + 1 位界定符 |
| ACK | ACK slot + 界定符（任何正确接收的节点都会拉显性） |
| EOF | 7 位隐性 |

另有远程帧（RTR）、错误帧、过载帧。**位填充**：连续 5 个相同电平后插入 1 个反相位。

### 2.3 位定时与采样点

一个位时间由 **Sync_Seg + Prop_Seg + Phase_Seg1 + Phase_Seg2** 组成（单位 TQ）：

```text
采样点 = (Sync_Seg + Prop_Seg + Phase_Seg1) / 总 TQ
```

- 经典 CAN 常用采样点 **87.5%**（CiA 301 建议）
- 采样点必须全网一致；不一致会在长线/高速下表现为随机错误帧
- 速率与长度强相关：1 Mbit/s≈40 m、500 kbit/s≈100 m、250 kbit/s≈250 m、125 kbit/s≈500 m、50 kbit/s≈1000 m

### 2.4 错误管理

- 每个节点维护 **TEC/REC** 错误计数
- ≤127：error-active；>127：error-passive；>255：**bus-off**（自动脱离总线）
- 错误类型：位错误、填充错误、CRC 错误、格式错误、ACK 错误

## 3 CAN FD

### 3.1 与 CAN 2.0 的关键差异

| 项目 | CAN 2.0 | CAN FD |
| --- | --- | --- |
| 载荷 | 0–8 B | **0–64 B**（DLC 编码 0–8/12/16/20/24/32/48/64） |
| 速率 | 单一速率 ≤1 Mbit/s | **双速率**：仲裁段 ≤1 Mbit/s，数据段可切到 2–5 Mbit/s（ISO） |
| 帧格式 | — | 新增 FDF、res、**BRS**（速率切换）、ESI |
| 远程帧 | 支持 | **不支持** |
| CRC | 15 位 | 17 位（≤16 B）/ 21 位（>16 B），CRC 段固定填充 + stuff count |

### 3.2 使用要点

- **BRS 位**决定数据段是否升速；升速后收发器的**环路延迟与对称性**要求更高，老式 CAN 收发器可能跑不了
- 数据段采样点常用 **70–80%**，仲裁段仍按经典 CAN 配置
- CAN FD 帧不能与经典 CAN 节点混跑：FD 帧到经典节点会触发错误帧；总线需要 **CAN FD tolerant** 收发器
- 控制器方案：MCP2518FD（SPI 接口）、TCAN4550（SPI + 集成收发器）、MCU 内置 FDCAN

### 3.3 和 Zynq 的关系（重要）

- **Zynq-7000 与 Zynq UltraScale+ 的 PS 都只有 2× CAN 2.0B，不支持 CAN FD**
- 要在 Zynq 上做 CAN FD，需要外挂 SPI 接口的 CAN FD 控制器（如 MCP2518FD），或在 PL 里实现 CAN FD IP

## 4 RS-485

### 4.1 它只是物理层

RS-485（TIA/EIA-485）只定义**差分电气特性**，不定义帧、地址、校验、仲裁——这些全交给上层协议（Modbus RTU、Profibus DP、DMX512 等）。

### 4.2 电气与拓扑

- 差分 **A/B（D+/D−）**，共模范围 **−7 V ~ +12 V**
- 半双工 2 线最常用；全双工用 4 线（TX 对 + RX 对）
- 多点：标准 32 个单位负载；用 1/8 UL 收发器可扩展到 256 节点
- **两端各 120 Ω 端接**；空闲态靠**失效保护偏置**（上拉/下拉）保证
- 长距离/强干扰场景用隔离收发器（ADM2587E、ISO3082）+ TVS/共模电感

### 4.3 速率与距离

- ≤100 kbit/s 时可到 **1200 m**
- 速率越高距离越短：1 Mbit/s 约 120 m，10 Mbit/s 只有十几米
- 距离上限的本质是**信号衰减 + 反射 + 共模漂移**，不是协议限制

### 4.4 方向控制

- 半双工必须控制 **DE/RE**：发送时使能驱动，接收时切回高阻
- 切换太慢会丢首字节，太快会撞总线 → 需要按波特率留 turnaround 时间
- Linux 下可用 `TIOCSRS485` ioctl 让 UART 自动控制 RTS 方向（见第 8 节）

## 5 SPI（速览）

- 4 线：**SCLK / MOSI / MISO / CS**，全双工，主机产生时钟
- 靠 **CS 片选**选从机，**没有地址、没有 ACK**
- 四种模式 = **CPOL × CPHA**（0/1/2/3），主从必须一致
- 速率可到几十甚至上百 MHz，但只适合**板内短距**
- 细节（时序图、模式判断、Linux 设备树、AD9361 实例）见 [[概念-SPI总线与四种模式]]

## 6 I2C

### 6.1 电气基础

- **SDA / SCL 开漏输出 + 上拉电阻**，线与：任何设备拉低即为低
- 标准模式总线电容上限约 **400 pF**，这是"只能板内、不能拉长线"的根本原因
- 上拉阻值权衡：太大 → 上升沿慢；太小 → 低电平 VOL 超标、功耗大

### 6.2 协议要点

| 项目 | 说明 |
| --- | --- |
| 地址 | 7-bit（约 112 个可用地址）或 10-bit |
| 帧边界 | START / 重复 START / STOP |
| 应答 | 每字节后第 9 个时钟：ACK（拉低）/ NACK |
| 多主 | 逐位仲裁（线与），失败方自动退出 |
| 时钟拉伸 | 从机可拉低 SCL 让主机等待（clock stretching） |
| 速率 | 标准 100 k、快速 400 k、Fast Plus 1 M、高速 3.4 M、超快速 5 M（单向） |

### 6.3 常见故障

- **地址冲突**：同一条总线挂两个相同地址器件（常见于传感器模块）
- **总线锁死**：从机在传输中被复位，SDA 一直被拉低 → 用 9 个 SCL 脉冲 + STOP 恢复
- 上拉/电平不匹配（3.3 V 器件接 5 V 总线）→ 需要电平转换
- 长排线/多器件导致电容超标 → 上升沿变缓、误码

## 7 选型决策

| 需求 | 首选 |
| --- | --- |
| 多主、广播、抗干扰、几十米到千米 | **CAN** |
| 同上但要更大载荷/更高吞吐（车载、工业新平台） | **CAN FD** |
| 只要远距离可靠串行、成本低、点对多点 | **RS-485**（配 Modbus RTU） |
| 板内高速、低延迟、数据流（ADC/DAC/Flash/RF） | **SPI** |
| 板内多器件、引脚少、要地址 | **I2C** |
| 需要长距离 + 多主 + 大带宽 | 都不合适 → 以太网（见 [[概念-串口与以太网-通信与丢包对比]]） |

一句话记忆：**RS485 管"电气"，CAN 管"仲裁与可靠"，SPI 管"快"，I2C 管"省引脚"。**

## 8 Linux 下怎么用

| 总线 | 内核接口 | 常用命令/API |
| --- | --- | --- |
| CAN | SocketCAN（`can` / `can_raw` / `can_bcm`） | `ip link set can0 type can bitrate 500000`；`candump can0`、`cansend can0 123#1122`、`cangen`；`ip -details -statistics link show can0` |
| CAN FD | SocketCAN + `CAN_RAW_FD_FRAMES` | `ip link set can0 type can bitrate 500000 dbitrate 2000000 fd on` |
| RS-485 | 串口 + `TIOCSRS485` | `struct serial_rs485` 设置 `SER_RS485_ENABLED`、`SER_RS485_RTS_ON_SEND`、延时；或 `rs485conf` 工具 |
| SPI | `spidev`（`/dev/spidevB.C`）或专用驱动 | `spi-config`/`spidev_test`；设备树 `spi-max-frequency`、`spi-cpol`、`spi-cpha` |
| I2C | `i2c-dev`（`/dev/i2c-N`）或专用驱动 | `i2cdetect -y 1`、`i2cget`、`i2cset`、`i2cdump` |

## 9 与本项目相关的落点

- **ZCU670**：板上的 Si5381 / 8A340001 时钟芯片走 **I2C**（UG1530 有说明）；RF 前端（如 AD9361）走 **SPI**（见 [[学习-Linux-驱动开发-AD9361-从零到通]]）
- **Zynq-7000 / ZynqMP PS**：CAN 均为 2.0B，**无 CAN FD**；要 FD 得外挂控制器或 PL IP
- **RS-485**：常见于板外控制链路/传感器，Linux 侧注意方向控制与失效偏置

## 10 常见坑清单

1. CAN 端接电阻装在每个节点上（错）——只在**总线物理两端**各一个 120 Ω
2. CAN 采样点全网不一致 → 长线随机错误
3. CAN FD 数据段用了老收发器 → 高速段误码
4. RS-485 忘切方向 / 切换延时不够 → 丢首字节
5. RS-485 无失效偏置 → 空闲时总线浮空、误触发
6. I2C 上拉过大或总线电容超标 → 上升沿塌陷
7. I2C 地址冲突 / 从机复位导致 SDA 锁死
8. SPI 模式（CPOL/CPHA）或 CS 建立保持时间不匹配
9. 3.3 V 与 5 V 电平直连，未做电平转换
