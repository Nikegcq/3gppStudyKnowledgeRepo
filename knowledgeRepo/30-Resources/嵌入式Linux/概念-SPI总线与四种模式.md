# 概念：SPI 总线与四种模式（驱动专题）

## 一句话总结

SPI 用 **SCLK / MOSI / MISO / CS** 四根线做全双工移位通信；所谓**四种模式**只是 **CPOL（空闲电平）× CPHA（采样相位）** 的 2×2 组合，主机与从机必须约定一致，否则读写全乱。Linux 里用设备树 `spi-cpol` / `spi-cpha` / `spi-max-frequency` 等属性配置，例如 Pluto 上的 AD9361。

---

## 1. SPI 信号线

| 信号 | 方向（相对主机） | 作用 |
|------|------------------|------|
| **SCLK** | 输出 | 移位时钟，由 Master 产生 |
| **MOSI** | 输出 | Master Out Slave In，主机发 |
| **MISO** | 输入 | Master In Slave Out，从机发 |
| **CS / SS** | 输出（通常低有效） | 片选，选中从机 |

```text
        Master                      Slave
        ┌─────┐                    ┌─────┐
   CS ──│     │────────────────────│     │
  SCLK ─│     │────────────────────│     │
  MOSI ─│     │────────────────────│     │
  MISO ─│     │◄───────────────────│     │
        └─────┘                    └─────┘
```

要点：

- **全双工**：每个 SCLK 边沿可同时移出/移入 1 bit  
- **无从机地址**：靠 CS 选器件（与 I²C 不同）  
- **无应答机制**：协议正确性靠时序与寄存器约定  

---

## 2. 四种模式怎么来的

两个开关：

| 参数 | 全称 | 问题 |
|------|------|------|
| **CPOL** | Clock Polarity | 空闲时 SCLK = 0 还是 1？ |
| **CPHA** | Clock Phase | 在时钟的**第几条边**采样数据？ |

模式数 = CPOL × CPHA：

$$
N_{\mathrm{mode}} = 2 \times 2 = 4
$$

| Mode | CPOL | CPHA | 空闲 SCLK | 常见采样边（记忆用） |
|------|------|------|-----------|----------------------|
| **0** | 0 | 0 | 低 | 上升沿采样 |
| **1** | 0 | 1 | 低 | 下降沿采样 |
| **2** | 1 | 0 | 高 | 下降沿采样 |
| **3** | 1 | 1 | 高 | 上升沿采样 |

具体边沿以器件手册时序图为准。

```text
Mode 0                          Mode 1
SCLK: __┌──┐  ┌──┐__           SCLK: __┌──┐  └──┘__
         └──┘  └──┘                    上升沿采样 vs 下降沿（CPHA 不同）

Mode 2（空闲高）                 Mode 3（空闲高）
SCLK: ‾‾└──┘  ┌──‾‾            SCLK: ‾‾└──┘  ┌──‾‾
CPOL=1：极性与 Mode 0 相反      CPHA 再决定第几条边采
```

## 3. 为什么不是「只有一种」SPI？

1. **从机内部触发器习惯不同**  
   有的芯片上升沿锁存，有的下降沿；空闲默认电平也不同。

2. **建立/保持时间（setup/hold）**  
   CPHA 决定数据相对时钟提前还是延后变化，便于走线延迟后仍在采样沿稳定。

3. **历史生态**  
   早期 MCU、Flash、传感器时序各异，SPI 没有强制唯一标准，于是做成可配置 4 模式。

4. **同一总线多从机**  
   不同从机模式可能不同，主机要么分时改模式，要么选兼容型号。

本质：SPI 只约定「**片选 + 移位**」，不唯一规定「哪条边代表有效」，故用 CPOL/CPHA 组合覆盖 4 种合法时序。

---

## 4. 主从必须一致（配错会怎样）

| 错误 | 典型现象 |
|------|----------|
| CPOL 不同 | 空闲电平反了，边沿语义反了，常读到全 0 / 全 FF / 乱码 |
| CPHA 不同 | 采样点错开半拍，采在跳变沿上，数据不稳定、偶发错误 |
| 波特率过高 | 建立时间不够，位错误 |
| CS 时序不对 | 从机不响应或帧错位 |

**规则：Mode 编号（或 CPOL/CPHA）主从必须相同。**

## 5. Linux / 设备树怎么配

### 5.1 常见 DT 属性

| 属性 | 含义 |
|------|------|
| `spi-cpol` | CPOL=1 |
| `spi-cpha` | CPHA=1 |
| 两者都无 | 多为 Mode 0（CPOL=0, CPHA=0） |
| `spi-max-frequency` | 最高 SCLK |
| `reg = <n>` | 片选 CSn |

### 5.2 Pluto / AD9361 示例

```dts
&spi0 {
    ad9361-phy@0 {
        compatible = "adi,ad9363a";
        reg = <0>;                      /* CS0 */
        spi-cpha;                       /* 相位 */
        spi-max-frequency = <10000000>; /* 10 MHz */
        ...
    };
};
```

含义：

- 内核 SPI 控制器按该从设备的模式驱动时钟  
- `ad9361_spi_check()` 会读实际通信速率  
- **AD9361 的 CPOL/CPHA 以 UG-570 / Datasheet 的 SPI 时序图为准**，DT 与手册必须对齐  

详见：[[学习-Linux-驱动开发-AD9361-从零到通]]、[[学习-Linux-驱动开发-AD9361-从dtsi到驱动调用流程]]

### 5.3 驱动侧常见路径（概念）

```text
用户态 / sysfs
  → IIO 属性（如频率、增益）
  → ad9361.c 内部函数
  → spi_write_then_read / spi_sync
  → 控制器驱动产生 SCLK/CS/MOSI 波形
```

Linux 要点：

| 概念 | 说明 |
|------|------|
| `struct spi_device` | 一个从设备（含 mode、max_speed_hz） |
| `struct spi_driver` | 从设备驱动，`id_table` / `of_match` 匹配 |
| `spi_transfer` / `spi_message` | 一次传输的缓冲与时序 |
| `spi-cpha` 等 | of 层解析进 `spi_device.mode` |

## 6. 和其它总线对比

| | SPI | I²C |
|--|-----|-----|
| 线数 | 4（+多 CS） | 2（SDA/SCL） |
| 寻址 | CS 硬件片选 | 7-bit 地址 |
| 速度 | 通常更快（可达数十 MHz） | 标准 100k/400k/更高 |
| 双工 | 全双工 | 半双工 |
| 应答 | 无标准 ACK | 有 ACK |
| 模式 | 4 种 CPOL/CPHA | 无「模式」概念，靠时序规范 |

## 7. 调试清单

1. 示波器看 **SCLK 空闲电平** → 定 CPOL  
2. 看 **MOSI/MISO 在哪条边稳定** → 定 CPHA  
3. 确认 **CS 在整帧有效**  
4. 读芯片 ID 寄存器（如 AD9361 PRODUCTID）验证通路  
5. 降 `spi-max-frequency` 排除信号完整性  
6. 对照手册 Mode 编号改 DT，再 `dmesg` 看 probe / `spi_check`

## 9. 口诀

```text
四线 SPI：时钟、两数据、片选；
模式四种：极性 CPOL × 相位 CPHA；
空闲高低、边沿采数，主从必须一致；
Linux 设备树写 cpol/cpha/max-freq；
AD9361 用 SPI 调参，IQ 走并口不走 SPI。
```
