# 概念：嵌入式总线原理详解（CAN / CAN FD / RS485 / SPI / I2C）

## 一句话总结

五套总线的"原理"可以归结为三个物理/逻辑技巧：**差分传输**（CAN、RS485 抗干扰）、**线与**（CAN 仲裁、I2C 仲裁与应答）、**移位寄存器**（SPI 全双工）。看懂这三件事，剩下的都是成帧与时序细节。

## 0 三个底层技巧

| 技巧 | 用在 | 原理 | 带来的能力 |
| --- | --- | --- | --- |
| **差分传输** | CAN、RS485 | 两根线反相驱动，接收端只看差值；共模干扰同时叠加在两线上被抵消 | 长距离、强干扰环境 |
| **线与（wired-AND）** | CAN、I2C | 所有节点只能把线拉低（或拉显性），任意一个拉低即为低 | 多主仲裁、应答、错误检测 |
| **移位寄存器** | SPI | 主从各一个移位寄存器首尾相接成环，时钟每跳一次交换 1 bit | 全双工、极高吞吐、零协议开销 |

## 1 CAN 2.0 原理

### 1.1 电气层：显性/隐性 = 线与

```
            dominant(0)          recessive(1)
CAN_H  ──┐        ┌──        ────────────────  ~2.5V
         └────────┘
CAN_L  ──┘        └──        ────────────────  ~2.5V
         (CAN_H≈3.5V, CAN_L≈1.5V, 差值≈2V)      (差值≈0V)
```

- 隐性（1）：两线都约 2.5 V，差分≈0
- 显性（0）：CAN_H 拉高、CAN_L 拉低，差分≈2 V
- **任意一个节点发显性，总线就是显性** → 线与

| 节点 A | 节点 B | 总线 |
| --- | --- | --- |
| 1 | 1 | 1 |
| 0 | 1 | **0** |
| 0 | 0 | 0 |

这条规则直接产生了 CAN 的两个核心能力：**非破坏性仲裁**和**ACK**。

### 1.2 位定时与同步

一个位时间被切成若干 **TQ（Time Quantum）**：

```
| Sync_Seg | Prop_Seg | Phase_Seg1 | Phase_Seg2 |
                          ↑
                       采样点
```

- **Sync_Seg**：固定 1 TQ，用于硬同步（SOF 的下降沿）
- **Prop_Seg**：补偿收发器 + 电缆传播延迟
- **Phase_Seg1/2**：吸收振荡器漂移，重同步时通过 SJW 加长/缩短
- 采样点位置 = (Sync + Prop + Phase1) / 总 TQ；经典 CAN 常取 **87.5%**
- 每个隐性→显性跳变都可作为重同步边沿；**位填充保证最多 5 个相同位就有一个边沿**，不会长时间失去同步

为什么速率和距离挂钩：一个位时间内必须让所有节点都看到同一个位值。线越长、收发器环路延迟越大，位时间就必须越长（速率越低）。

### 1.3 仲裁：CSMA/CR

所有待发送节点在总线空闲（3 位间歇）后**同时发 SOF**，然后逐位比较 ID：

```
节点A ID: 0 0 1 0 ...
节点B ID: 0 0 1 1 ...   ← 第4位发1，却读到0
总线    : 0 0 1 0 ...
                  ↑ B 失去仲裁，立即转为接收
```

- 发"1"却读到"0"的节点输掉仲裁，**不破坏当前帧**，稍后自动重试
- **ID 数值越小优先级越高**（0 是显性）
- 这叫 CSMA/CR（Collision Resolution），不是以太网的 CSMA/CD（冲突检测后放弃重发）

### 1.4 成帧

```
SOF | 仲裁段(ID+RTR) | 控制(IDE,r0,DLC) | 数据(0-8B) | CRC15 | ACK | EOF(7)
```

- **CRC**：发送方算 CRC-15，接收方校验；不一致就发错误帧
- **ACK slot**：发送方发隐性，**任何正确接收的节点都拉显性** → 发送方读到显性即"至少有人收到"
- **位填充**：连续 5 个相同位后强制插入 1 个反相位；接收端自动去掉
- 错误帧 = 6 个连续显性位（故意违反填充规则），让全网立刻知道出错

### 1.5 错误 confinement

每个节点有发送错误计数 TEC、接收错误计数 REC：

| 状态 | 条件 | 行为 |
| --- | --- | --- |
| error-active | TEC/REC ≤127 | 正常发主动错误帧 |
| error-passive | >127 | 只能发被动错误帧，退让更久 |
| bus-off | TEC >255 | 自动脱离总线，等待恢复 |

设计意图：**局部故障不能拖垮整条总线**——坏节点会自己逐步退出。

## 2 CAN FD 原理

### 2.1 为什么要双速率

经典 CAN 的瓶颈不是"线不够快"，而是**仲裁段必须在全网同步的低速率下进行**（所有节点都要能逐位比较）。CAN FD 的思路是：

- **仲裁段仍用低速率**（保证兼容与同步）
- 仲裁结束后用 **BRS 位**切到高速率传数据
- 载荷从 8 B 提升到 64 B，把仲裁开销摊薄

```
SOF | 仲裁段(≤1M) | 控制 | BRS=1 → 数据段(2-5M) | CRC | ACK | EOF
                              ↑ 切高速                 ↑ 切回低速
```

### 2.2 帧格式新增位

| 位 | 作用 |
| --- | --- |
| **FDF** | 1=CAN FD 帧，0=经典 CAN 帧 |
| **res** | 保留位（显性） |
| **BRS** | 1=数据段切高速 |
| **ESI** | 发送方错误状态（1=error passive） |
| DLC | 4 位编码 0–8/12/16/20/24/32/48/64 字节 |

**取消远程帧**（RTR 不再使用）。

### 2.3 CRC 与填充的强化

- 载荷变长后，经典 15 位 CRC 的漏检率不够 → 改为 **17 位（≤16 B）/ 21 位（>16 B）**
- CRC 段使用**固定填充位**（每 4 位插 1 位）+ **stuff count**（3 位计数 + 奇偶位），保证长帧也有足够边沿、且填充可被校验

### 2.4 为什么对收发器要求更高

数据段位时间可能只有 200 ns（5 Mbit/s）。收发器从 TX 到 RX 的**环路延迟**和上升/下降**对称性**必须远小于一个位时间，否则采样点漂移。

```
控制器 TX → 收发器 → 总线 → 收发器 → 控制器 RX
└──────────── 环路延迟必须 << 数据段位时间 ────────────┘
```

所以：老式 CAN 收发器可能只能跑 1–2 Mbit/s；CAN FD 需要专门的低延迟收发器。

## 3 RS-485 原理

### 3.1 差分驱动

```
驱动器:  A ──┐            ┌──   A>B 表示 1（或 0，取决于约定）
            └────────────┘
         B ──┐            ┌──   B>A 表示 0
            └────────────┘
接收器:  V_AB = V_A − V_B，> +200 mV 为一种逻辑，< −200 mV 为另一种
```

- 干扰以**共模**形式同时叠加到 A、B → 相减后抵消
- 共模范围 −7 V ~ +12 V；超出需隔离或改接地

### 3.2 为什么必须端接

当线长与信号波长可比时，电缆就是**传输线**，特性阻抗约 100–120 Ω。信号到达末端若阻抗不匹配会**反射**，与后续信号叠加造成误码。

```
发送端 ──────────────── 接收端
  120Ω                     120Ω
  （匹配电缆特性阻抗，吸收反射）
```

只在**物理两端**各接一个 120 Ω；中间节点不接。

### 3.3 空闲态与失效保护

所有驱动器关闭时总线是高阻，差分电压可能落在不确定区。解决：**失效保护偏置**——A 上拉、B 下拉（经电阻），保证空闲时差分 > +200 mV（稳定的 mark 态）。

### 3.4 方向控制与半双工

```
MCU UART_TX ──→ DI ─┐
                    ├─ 收发器 ── A/B ── 总线
MCU UART_RX ←── RO ─┘
MCU GPIO   ──→ DE/RE  （发送时使能，接收时高阻）
```

- 发送：DE 有效，驱动器占用总线
- 接收：DE 无效，驱动器高阻，接收器工作
- 切换必须等最后一个停止位**完全移出**，否则截断；切太慢则总线空闲时间过长

### 3.5 距离/速率原理

距离上限由三件事决定：**电缆高频衰减**、**反射**、**共模漂移**。速率越高，衰减与反射影响越大，所以"1200 m @ 100 kbit/s"和"十几米 @ 10 Mbit/s"是同一个物理规律的两端。

## 4 SPI 原理

### 4.1 移位寄存器环

```
Master                          Slave
┌──────────────┐   MOSI   ┌──────────────┐
│ 8-bit 移位寄存器 │ ───────→ │ 8-bit 移位寄存器 │
│                │ ←─────── │                │
└──────────────┘   MISO   └──────────────┘
        ↑ SCLK（主产生）              ↑
```

每个 SCLK 周期：主机移出 1 bit 到 MOSI，从机移出 1 bit 到 MISO，双方各移入 1 bit。**8 个周期后两个寄存器内容互换**——这就是"全双工"的本质，也是为什么 SPI 读写总是同时发生。

### 4.2 四种模式的来源

两个独立问题：

- **CPOL**：空闲时 SCLK 是高还是低？
- **CPHA**：在**第一个边沿**采样，还是**第二个边沿**采样？

| Mode | CPOL | CPHA | 采样边沿 |
| --- | --- | --- | --- |
| 0 | 0 | 0 | 上升沿（第一个） |
| 1 | 0 | 1 | 下降沿（第二个） |
| 2 | 1 | 0 | 下降沿（第一个） |
| 3 | 1 | 1 | 上升沿（第二个） |

```
Mode 0:  SCLK  __/‾\_/‾\_/‾\__
              ↑   ↑   ↑
           采样  采样  采样（上升沿）
```

### 4.3 为什么快

- 推挽驱动（不是开漏），边沿快
- 无地址、无仲裁、无 ACK、无重传 → **协议开销≈0**
- 时钟由主机独占产生，不需要时钟恢复

代价：没有流控、没有错误检测，从机想"反悔"只能拉 CS 或另接中断线；多从机需要多根 CS（或菊花链）。

## 5 I2C 原理

### 5.1 开漏 + 上拉 = 线与

```
VDD
 │
 Rp
 │
 ├──── SDA / SCL
 │
 ├─ 器件1（开漏）
 └─ 器件2（开漏）
```

- 任何器件只能**拉低**；释放后由上拉拉高
- 线与：任一器件拉低 → 总线为低
- 这条规则同时实现了：多主仲裁、ACK、时钟同步、时钟拉伸

### 5.2 起始/停止/数据有效性

```
START:  SCL=1 时 SDA 由 1→0
STOP :  SCL=1 时 SDA 由 0→1
数据 :  SCL=1 期间 SDA 必须稳定；SDA 只能在 SCL=0 时变化

SCL  ‾‾\__/‾‾\__/‾‾\__
SDA  ──<──X────X──────   （只在 SCL 低时变）
```

### 5.3 仲裁原理

多主同时发送时逐位比较：

- 某主机想发 1（释放 SDA），但读到 0 → 说明别人发了 0 → **它输掉仲裁**，立即停止驱动，转为接收
- 因为地址先发，**地址小的主机会赢**
- 输掉的主机不会破坏赢家的数据（非破坏性仲裁），稍后可重试

### 5.4 时钟同步与时钟拉伸

- SCL 也是线与：低电平时间 = 所有主机中最长的低电平；高电平 = 最短的高电平 → 自动同步
- 从机处理不过来时，可在 ACK 后**拉低 SCL** 不放 → 主机被迫等待（clock stretching）

### 5.5 ACK 与寻址

```
START | 7-bit 地址 | R/W | ACK | 数据8bit | ACK | ... | STOP
                            ↑ 从机拉低 SDA
```

- 每 8 位后第 9 个时钟是应答位：接收方拉低 = ACK，释放 = NACK
- 7 位地址 + 1 位读写；10 位地址用两个字节（`11110xx` + 低 8 位）
- 没有 CRC，只有 ACK；出错靠上层重试或总线复位

### 5.6 上拉电阻为什么难选

总线是 RC 网络（上拉 R × 总线电容 C）：

- R 太大 → 上升沿慢，高速下采样失败
- R 太小 → 器件拉低时灌电流过大，VOL 超标
- 约束：`Rp(max) ≈ tr / (0.8473 × Cb)`，`Rp(min) = (VDD − VOL) / IOL`

这也是 I2C 只能板内、总线电容约 400 pF 的原因。

## 6 五种协议原理对照

| 协议 | 物理层核心 | 链路层核心 | 可靠性来源 |
| --- | --- | --- | --- |
| CAN | 差分 + 显性/隐性线与 | 逐位仲裁 + 位填充 + CRC + ACK + 错误帧 | 硬件级错误检测与节点隔离 |
| CAN FD | 同 CAN | 双速率 + 更长载荷 + 更强 CRC | 同 CAN，数据段更高速 |
| RS-485 | 差分 + 端接 + 偏置 | 无（UART 提供字节帧） | 全靠上层协议（CRC/重试） |
| SPI | 推挽 + 独立时钟 | 移位寄存器 + CS | 基本没有，靠时序正确 |
| I2C | 开漏 + 上拉线与 | 地址 + ACK + 仲裁 + 时钟拉伸 | ACK + 上层重试 |
