# C++ 面试 — 内存管理与智能指针

## 1. new/delete 和 malloc/free 有什么区别？

### 口头答案

`malloc/free` 是 C 风格：分配/释放原始字节，返回 `void*`，不调用构造/析构，失败返回 `nullptr`。`new/delete` 是 C++：分配后**构造对象**，返回正确类型，可抛 `std::bad_alloc`，`delete` 时调析构；数组用 `new[]/delete[]`。现代代码优先容器与智能指针，少用裸 `new`。

### 关键点

| 维度 | malloc/free | new/delete |
|------|-------------|------------|
| 构造析构 | 无 | 有 |
| 类型 | `void*` | 类型化 |
| 失败 | `nullptr` | 异常（或 `nothrow`） |
| 可重载 | 否（可挂钩分配器） | 可重载类成员 |
| 配对 | malloc↔free | new↔delete，new[]↔delete[] |

### 易被追问

- 混用会怎样？→ 未定义行为，严禁混用。  
- `new (std::nothrow)`？→ 失败返回空，不抛异常。  
- placement new？→ 在已有内存上构造，不负责释放内存。

## 2. 堆和栈的区别？协议栈代码里怎么选？

### 口头答案

栈由编译器管理：进出作用域自动分配释放，速度快、碎片少，但空间有限，不适合超大缓冲。堆由程序员/智能指针管理：空间大、生命周期灵活，但分配有开销，易泄漏碎片。实时/热路径倾向：**小对象栈上 + 大缓冲预分配/池化**；跨异步生命周期的对象用堆 + 明确所有权。

### 关键点

| 维度 | 栈 | 堆 |
|------|----|----|
| 管理 | 编译器 | 程序员/库 |
| 速度 | 快 | 相对慢 |
| 空间 | 小 | 大 |
| 生命周期 | 作用域 | 直到 free/delete |
| 风险 | 溢出、悬空返回局部 | 泄漏、碎片、use-after-free |

### 易被追问

- 逃逸/延迟释放？→ 智能指针、对象池、arena。  
- 实时性？→ 避免帧内不可预测 `malloc`；启动时预分配。

## 3. 什么是 RAII？为什么现代 C++ 强调它？

### 口头答案

RAII（Resource Acquisition Is Initialization）：在构造函数里获取资源，在析构函数里释放；对象销毁与资源释放绑定。异常或提前 `return` 时栈回退仍会析构，资源不漏。`vector`、智能指针、`lock_guard` 都是 RAII。协议栈里锁、fd、DMA 缓冲所有权都应尽量 RAII 化。

### 关键点

```cpp
{
  std::lock_guard<std::mutex> lk(m);  // 构造加锁，析构解锁
  // 临界区
}  // 出作用域必解锁，含异常路径
```

原则：**不要手工配对 open/close、new/delete、lock/unlock**，除非底层 C API 边界且包了一层 RAII。

### 易被追问

- RAII 一定在栈上？→ 控制块在堆上也可以；关键是析构自动释放。  
- 和 GC 比？→ 确定性释放，适合实时与嵌入式。

## 4. unique_ptr 的特点与适用场景？

### 口头答案

`unique_ptr` 表达**独占所有权**：不可拷贝，可移动；通常无额外堆控制块，开销接近裸指针。离开作用域自动 `delete`。适合工厂返回、组件独占持有、Pimpl。`make_unique` 异常更安全。需要临时共享时 `shared_ptr(unique_ptr&&)` 转移或对同一所有权不共享。

### 关键点

```cpp
auto p = std::make_unique<MacScheduler>();
auto q = std::move(p);  // p 空，q 独占
```

- 数组：`unique_ptr<T[]>`  
- 自定义删除器：fclose、池回收  
- 不要 `get()` 后长期裸指针再 `delete`  

### 易被追问

- `get()` 返回的指针生命周期？→ 与 unique_ptr 相同；勿存储超过其生命周期。  
- 与共享？→ 用 `shared_ptr`；不要多个 unique 指同一对象。

---

## 5. shared_ptr 原理？何时用？

### 口头答案

`shared_ptr` 堆上控制块记录**强引用计数**（以及弱计数），最后一个 strong 销毁时析构对象并释放控制块。适合**多个所有者、生命周期不确定谁最后结束**的场景。拷贝增加计数，开销高于 unique_ptr（控制块 + 原子增减）。能独占就 unique，不够再 shared。

### 关键点

- `std::make_shared`：对象与控制块一次分配，更局部性、异常更安全  
- 原子计数：线程安全的是计数操作，不是对象本身  
- 不要用栈对象地址直接初始化 shared_ptr 走删除器乱用  

### 易被追问

- 线程安全？→ 不同 shared_ptr 实例拷贝/赋值在计数层面安全；同一实例多线程写不安全。  
- 性能热点？→ 计数竞争、控制块间接；热路径减少 shared 拷贝。

## 6. weak_ptr 解决什么问题？

### 口头答案

`weak_ptr` 观察资源但**不增加 strong 计数**，用于：① 打破 `shared_ptr` 循环引用；② 缓存/观察者，对象可能已销毁时安全感知。使用时 `lock()` 得到 `shared_ptr`，成功则保证期间存活，失败则对象已释放。

### 关键点

```cpp
std::weak_ptr<Peer> wp = peer_shared;
if (auto sp = wp.lock()) {
  // 对象仍活着
} else {
  // 已析构
}
```

### 易被追问

- 循环引用怎么形成？→ 成员互相 `shared_ptr`，见下一题。  
- `expired()`？→ 判断 strong 是否为 0，仍有 TOCTOU，优先 `lock()`。

## 7. shared_ptr 循环引用如何产生与避免？

### 口头答案

A 持有 `shared_ptr<B>`，B 又持有 `shared_ptr<A>`，双方析构都需对方先释放，引用计数无法归零，内存泄漏。打破方法：其中一边用 `weak_ptr`（通常是“子指向父”或“回指”用 weak），或改数据结构避免双向所有权。

### 关键点

```text
A --shared--> B
B --shared--> A   // 泄漏
B --weak----> A   // OK，lock 后临时访问
```

所有权设计问题，不只是智能指针“bug”。用 raw/weak 表达**非所有权关联**。

### 易被追问

- 观察者模式？→ 被观察者持有观察者常用 `weak_ptr`。  
- 树形结构？→ 父拥有子 `unique_ptr`，子回指父用 raw/weak。

## 8. 如何避免和排查内存泄漏？

### 口头答案

工程上优先：① 尽量不裸 `new`，容器+智能指针；② 所有权边界清晰（谁创建谁释放/转移）；③ 第三方 C 接口用自定义删除器 RAII。排查：ASan/LSan、valgrind、自定义分配计数、关键对象生命周期日志、代码审查关注异常路径与拷贝控制。

### 关键点

```text
预防：RAII + 所有权语义 + 代码审查
检测：ASan/LSan / valgrind / 业务层计数与对账
协议栈：缓冲池对账（分配数 == 回收数）比全局 heap 更有效
```

### 易被追问

- 只在异常时泄漏？→ 缺 RAII，手工 free 在 throw 前漏掉。  
- 循环引用漏检？→ heap 工具能报 unreachable，需结合设计审查。

## 9. 什么是内存对齐？对通信/协议栈为何重要？

### 口头答案

对象地址需满足类型对齐要求（如 4/8/16 字节），否则可能慢或在某些架构上故障。编译器会插入 padding。协议栈里：DMA/硬件缓冲常要求物理/缓存行对齐；网络报文解析需注意避免未对齐访问（或用 `memcpy`）；结构体字段布局影响带宽与 cache，连续数组比链表更 cache 友好。

### 关键点

- `alignas`、`std::aligned_alloc`、预分配缓冲池  
- `offsetof`、序列化时显式编码，不依赖 struct 内存布局跨平台  
- false sharing：多线程写同一 cache line 不同变量 → pad 到 cache line  

### 易被追问

- `#pragma pack`？→ 减 padding 省空间，可能牺牲性能/需注意对齐访问。  
- 结构体大小？→ 讲清对齐规则与 padding 示例即可。
